# 元启发式算法

元启发式算法是在可接受时间内搜索高质量解的一类通用框架。它通常不保证找到全局最优解，但会通过“强化搜索”和“多样化搜索”之间的平衡，避免普通贪心算法只停留在一个局部最优点。

本文面向柔性作业车间调度问题（FJSP）。目标是最小化最大完工时间：

$$
C_{\max}=\max_j C_j
$$

其中，$C_j$ 是工件 $j$ 的完工时间。任何候选解都必须满足：同一工件的工序按既定顺序加工；一道工序只能选择一台合法候选机器；同一机器同一时刻最多加工一道工序；加工过程不可中断。

## 一、共同基础：解的编码、解码与邻域

### 1. 解的编码

本项目的 ILS 使用“工件序列 + 机器向量”的双层编码。

- 工件序列决定工序被解码的先后次序。工件编号第 $k$ 次出现表示该工件的第 $k$ 道工序，因此序列中交换不同工件不会破坏工件内部的工艺顺序。
- 机器向量为每道工序记录一台合法候选机器。

例如，工件序列 `[0, 1, 0, 1]` 表示依次处理 $O_{0,0}$、$O_{1,0}$、$O_{0,1}$、$O_{1,1}$。

### 2. 解码与评价

解码时按工件序列逐项取出工序，在指定机器的时间表中寻找不早于其前序工序结束时间的最早可行空隙。所有工序排定后，以 $C_{\max}$ 作为目标值；数值越小，解越好。

这种解码方式会生成可行的主动调度：如果机器时间轴前部存在足够空隙，工序可以插入空隙，而不是一律追加到最后。

### 3. 邻域结构

邻域是从当前解经过一次小改动可以到达的解集合。本项目使用两类动作：

1. **序列交换**：交换工件序列中两个不同工件的位置，改变工序优先次序。
2. **机器重分配**：把一道柔性工序改派到另一台合法候选机器。

前者主要优化工序排序，后者主要优化机器负载。组合使用能同时搜索 FJSP 的两个决策维度。

## 二、ILS：迭代局部搜索

ILS 是 **Iterated Local Search** 的缩写，中文通常译为“迭代局部搜索”。它不是简单地重复同一次局部搜索，而是对已经得到的局部最优解进行扰动，再从新区域继续局部搜索。

### 1. 基本原理

普通局部搜索从初解出发，反复选择更好的邻居：

$$
s'\in N(s),\qquad f(s')<f(s)
$$

直到邻域中没有更优解。此时得到的是关于当前邻域的局部最优解，不一定是全局最优解。ILS 通过扰动跳出该区域，其主循环为：

1. 构造初始可行解 $s_0$。
2. 对 $s_0$ 做局部搜索，得到局部最优解 $s$。
3. 扰动 $s$，得到相距较远的解 $s'$。
4. 对 $s'$ 再做局部搜索，得到 $s''$。
5. 根据接受准则决定下一轮从 $s$ 还是 $s''$ 出发。
6. 更新搜索期间发现的全局最好解。
7. 满足终止条件后输出全局最好解。

可以写成：

$$
s'=\operatorname{Perturb}(s),\qquad
s''=\operatorname{LocalSearch}(s')
$$

### 2. 四个核心组成部分

#### 初始解

初始解影响搜索起点，但不决定最终结果。本项目使用 MWKR-EET 启发式产生初解：优先调度剩余估计工作量最大的工件，并选择使当前工序最早结束的机器。对 `la01_vdata`，该初解的最大完工时间为 589。

#### 局部搜索

在交换邻域和机器重分配邻域中抽样，选择本轮发现的最好改进邻居。只接受严格改善，直到没有找到改进或达到局部搜索轮数上限。

#### 扰动

扰动连续执行若干次随机邻域动作。扰动太弱时容易回到原局部最优；太强时会丢失当前解中的优良结构，近似随机重启。实际使用时应根据连续无改进次数动态调节扰动强度。

#### 接受准则

本项目接受不劣于当前解的候选局部最优解，并始终单独保存全局最好解。每隔固定轮数从全局最好解重新出发，避免搜索长期漂移到较差区域。其他常见方案还包括只接受更优解、允许以小概率接受较差解，以及基于历史质量设置阈值。

### 3. 伪代码

```text
s = LocalSearch(BuildInitialSolution())
best = s
while 未满足终止条件:
    candidate = Perturb(s)
    candidate = LocalSearch(candidate)
    if Accept(candidate, s):
        s = candidate
    if f(candidate) < f(best):
        best = candidate
return best
```

### 4. 关键参数与终止条件

| 参数 | 作用 | 取值过小 | 取值过大 |
| --- | --- | --- | --- |
| ILS 迭代次数 | 控制扰动与重搜索次数 | 搜索不足 | 运行时间增加 |
| 邻域抽样数 | 控制每轮检查的邻居数量 | 容易漏掉改进 | 单轮开销增加 |
| 局部搜索轮数 | 控制强化搜索深度 | 未到局部最优 | 后期可能无效计算 |
| 扰动强度 | 控制跳离当前区域的距离 | 难以跳出局部最优 | 优良结构被破坏 |

常见终止条件包括固定迭代次数、固定运行时间、连续若干轮未改善，或达到已知下界。为了便于复现实验，应记录随机种子、参数、初解、最好解和运行时间。

### 5. 优缺点

- 优点：结构清晰；能直接复用已有局部搜索；参数相对较少；容易组合问题专用邻域。
- 缺点：性能高度依赖邻域和扰动设计；局部搜索可能占用大部分时间；过于严格的接受准则会降低多样性。

## 三、TS：禁忌搜索

TS 是 **Tabu Search** 的缩写，中文为“禁忌搜索”。其核心思想是允许搜索走向暂时更差的解，同时用短期记忆禁止立即撤销近期动作，从而越过局部最优附近的障碍。

### 1. 基本原理

在每一轮中，TS 通常选择当前允许邻域内评价最好的解，即使它比当前解差：

$$
s_{t+1}=\arg\min_{s'\in N(s_t)\setminus T_t} f(s')
$$

其中，$T_t$ 表示当前被禁忌表限制的动作或属性。移动后，把该动作的反向操作加入禁忌表，并在其禁忌期限到期后释放。

### 2. 禁忌表

禁忌表不宜直接保存完整解，通常保存动作属性。例如：

- 序列交换后，短期内禁止把同一对工序立即交换回来。
- 机器重分配后，短期内禁止该工序立刻返回原机器。

禁忌期限过短容易产生循环；过长会排除过多有价值的邻居。期限可以固定，也可以在区间内随机变化。

### 3. 特赦准则

禁忌不是绝对限制。如果一个禁忌动作能产生优于历史全局最好值的解，通常允许执行，这称为特赦准则：

$$
f(s')<f(s_{best})\Rightarrow \text{允许该禁忌动作}
$$

特赦能避免禁忌表错误地挡住非常有价值的解。

### 4. 强化与多样化

- **强化**：提高优秀解中常见结构的选择概率，深入搜索有希望的区域。
- **多样化**：惩罚频繁出现的动作或结构，鼓励探索较少访问的区域。

TS 必须始终单独保存全局最好解，因为当前解可能为了越过局部最优而暂时变差。

### 5. 伪代码

```text
s = BuildInitialSolution()
best = s
tabu = empty
while 未满足终止条件:
    candidates = GenerateNeighborhood(s)
    allowed = 非禁忌候选 + 满足特赦准则的禁忌候选
    s = allowed 中评价最好的解
    更新禁忌表及禁忌期限
    if f(s) < f(best):
        best = s
return best
```

### 6. 关键参数与特点

关键参数包括禁忌期限、候选邻域规模、无改进上限和多样化强度。TS 的优点是能系统地避免短期循环、越过局部最优，且历史信息利用充分；缺点是需要设计合适的禁忌属性与期限，较大邻域的逐项评价也可能很耗时。

## 四、SA：模拟退火

SA 是 **Simulated Annealing** 的缩写，中文为“模拟退火”。它借鉴固体降温过程：高温阶段允许较大范围波动，低温阶段逐渐稳定到高质量区域。

### 1. 接受概率

设当前解为 $s$，候选解为 $s'$，最小化问题中的目标差为：

$$
\Delta=f(s')-f(s)
$$

若 $\Delta\le 0$，候选解不差于当前解，直接接受；若 $\Delta>0$，以如下概率接受较差解：

$$
P(\text{accept})=\exp\left(-\frac{\Delta}{T}\right)
$$

温度 $T$ 较高时，较差解仍有较大概率被接受，有利于跳出局部最优；温度下降后，算法越来越偏向改善动作。

例如，$\Delta=10$：当 $T=100$ 时接受概率约为 0.905；当 $T=5$ 时约为 0.135。

### 2. 冷却计划

常用几何冷却为：

$$
T_{k+1}=\alpha T_k,\qquad 0<\alpha<1
$$

其中，$\alpha$ 常取接近 1 的数。初温过低会使 SA 退化为普通局部搜索；初温过高会长时间近似随机游走。降温过快容易过早冻结，降温过慢则运行时间很长。

可通过抽样邻域目标差来设置初温：先确定期望的初始劣解接受率 $p_0$，再用典型正目标差 $\overline{\Delta^+}$ 估计：

$$
T_0=-\frac{\overline{\Delta^+}}{\ln p_0}
$$

### 3. 伪代码

```text
s = BuildInitialSolution()
best = s
T = InitialTemperature()
while T > 最低温度 且未满足其他终止条件:
    repeat 每个温度的迭代次数:
        candidate = RandomNeighbor(s)
        delta = f(candidate) - f(s)
        if delta <= 0 or random() < exp(-delta / T):
            s = candidate
        if f(s) < f(best):
            best = s
    T = alpha * T
return best
```

### 4. 关键参数与特点

关键参数包括初始温度、最低温度、冷却率、每个温度的迭代次数和邻域动作比例。SA 的优点是原理简单、内存需求小，并能以概率方式跳出局部最优；缺点是参数尺度与目标函数紧密相关，冷却计划不合适时容易随机游走或过早收敛。

## 五、ILS、TS 与 SA 的比较

| 比较内容 | ILS | TS | SA |
| --- | --- | --- | --- |
| 跳出局部最优的方式 | 扰动后重新局部搜索 | 允许走差并禁止近期反向动作 | 按温度以概率接受较差解 |
| 主要记忆 | 当前解与全局最好解 | 禁忌表、频率等历史信息 | 当前温度，通常不需长期记忆 |
| 搜索单位 | 局部最优解之间跳转 | 每轮选择允许邻域中的最好解 | 每轮随机生成一个或少量邻居 |
| 核心参数 | 扰动强度、局部搜索深度 | 禁忌期限、候选集规模 | 初温、冷却率、温度长度 |
| 主要优势 | 易复用高质量局部搜索 | 防循环且历史利用充分 | 简洁、允许受控随机走差 |
| 主要风险 | 扰动设计不佳 | 禁忌属性或期限不合适 | 温度计划不合适 |

三者并非互斥。例如，可以在 ILS 的接受阶段采用 SA 概率，也可以用 TS 作为 ILS 的局部搜索器。选择方法时应先保证编码和解码正确，再根据实例规模、可用运行时间以及邻域评价成本调整搜索框架。

## 六、本项目的实验规范

1. 先用启发式算法构造可行初解，并记录初始 $C_{\max}$。
2. 每次生成或接受新解后，检查工序优先约束、候选机器合法性和机器互斥约束。
3. 固定并报告随机种子；比较算法时使用相同实例和相近计算预算。
4. 同时报告最好值、相对下界差距、运行时间和多次独立运行的均值与标准差。
5. 不把某一次随机运行的改善视为算法普遍优越；最终应进行多随机种子、多实例实验。

批量运行 `data` 中的 vdata 与 Brandimarte 实例：

```powershell
python Metahe/ILS.py
```

默认结果保存到 `Metahe/performance_ils.csv`。也可以指定搜索参数和输出路径：

```powershell
python Metahe/ILS.py --iterations 100 --seed 42 --local-trials 350 --local-rounds 12 --output Metahe/performance_ils.csv
```
